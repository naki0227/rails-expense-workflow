## 変更理由
- 認証機能は Devise に任せて、業務アプリの本題に集中したい
- `User` の role は読みやすさのために enum で扱いたい
- model を作ったら spec を一緒に作る方針にしたい
- CI を先に作って、以後の実装を同じ基準で守りたい

## 今日わかったこと
- システム Ruby のまま進めると権限で詰まりやすい
- `rbenv` は `.ruby-version` と `PATH` 設定の両方が大事
- 学習用でも、最初にテスト基盤を整える価値が大きい
- 設定ファイルは「何のための設定か」を言葉にすると理解しやすい
- Devise の生成物は認証の標準部分で、業務に必要な `name` や `role` は自分で足す
- `enum` と validation は役割が違うので、両方考える必要がある
- GitHub Actions は最初から全部入りより、今必要な最小版から始める方が理解しやすい

## 詰まったこと
- `rbenv local` をしても `.zshrc` 設定前は Ruby が切り替わらなかった
- `rails` コマンドが見つからず `rbenv rehash` が必要だった
- shoulda-matchers の設定構文で `=` を使ってしまった
- spec で `expect` の比較対象に使うハッシュのキー形を意識する必要があった
- CI の `services`, `options`, `DATABASE_URL`, `run: |` の書き方で迷った
